# merge_damages 的解析优先级契约(数组前 6 元 + 后 3 元装载)

`damage_system::merge_damages` 返回固定的 `[(DamageType, Option<Effect<S>>); 9]`,前 6 元顺序为 `[破防护盾, 破奥术盾, 奥术, 剪切, 冲击, 真实]`(破盾优先 → 有防护 → 真实),后 3 元为 `[仅防护盾, 仅替身盾, 仅奥术盾]`(Only* 装载型,追加末尾)。

前 6 元的顺序**不是实现细节**:`apply_damages` 按它结算护盾命中次序,并决定 `DamageInfo` 死因记录的是"数组解析序中第一个 hurt 类型"。等级 B 测试将其钉为契约(顺序契约测试 + 行为断言按类型查找)。

Only* 装载型(后 3 元)追加于末尾,不参与破盾/伤害的解析序,也不记死因(`is_hurt_heal = false`)。它们与伤害类型是正交语义:装载只作用于单个对应护盾。

未来若把数组改为 HashMap/Vec 等灵活结构,必须保留该解析优先级,否则护盾命中次序与死因判定会悄悄改变。等级 C 加深 `UpsertContainer` 语义时同样不可改动该契约。
